# iFan 风扇控制行为分析

日期：2026-11-02。研究对象为 iFan 1.1.3，仅用于理解与 Mac Go 风扇控制有关的兼容性行为；未修改 iFan 或其服务。

## 方法与范围

使用隔离的 REA 6.8.0 CLI、Node 22.23.4，以及 Apple LLVM / otool 做本机只读分析。REA 用于应用构成、动态库解析和原生方法元数据检查；没有使用未安装的 Hopper、Ghidra 或 IDA 深度反编译引擎。

原始应用、二进制、诊断文件和分析工具缓存不随此仓库发布。以下为观察结论，不包含完整反汇编或可重建第三方程序的代码。

## 观察到的调用链

1. 主程序将应用内的 `SMC` 资源 CLI 路径交给其管理员服务。
2. 最大转速分支先发送手动模式请求，再发送目标 RPM；调用侧不在两者之间立即要求模式读回已变为手动。
3. 管理员服务通过资源 CLI 执行实际控制。
4. CLI 先探测小写 `F<n>md`，不存在时采用 `F<n>Md`。模式写请求获接受后继续操作，只有写请求被拒绝时才尝试 `Ftst` 后备路径。
5. 速度路径将 Float 目标写入 `F<n>Tg`。该 CLI 的成功返回本身不证明最终模式与实际转速已稳定。
6. IOKit 连接使用 type 0，传输使用 selector 2 和 80 字节 packet，与本项目采用的传输约定一致。

这些观察仅对应所分析版本，不应外推为所有 iFan 版本或所有 Mac 的行为。

## 对早期实现的启示

在一台 Apple M4 设备上，只读检查发现 `F0Md` 与 `F0Tg` 存在，而 `F0md`、`Ftst` 和 `FS! ` 不存在。早期开发版在模式写请求获接受后立即读回模式，可能在固件尚未发布新状态时过早进入失败路径。

继续写入目标后，首帧目标读回仍可能暂时不等于请求值。早期版本曾因此报告失败并恢复自动，表现为风扇短暂加速后下降。

修正策略为：在已校验范围内发送模式和目标请求，然后在有界时间内成对观察模式与目标，要求连续两次同时确认。等待期间不重复写目标；传输错误、格式错误和原始固件拒绝仍保留并报告。恢复自动同样有限等待模式读回，不依赖目标值或实际 RPM。

主程序心跳还需要在菜单跟踪和系统模态期间继续执行，并使超时回调匹配其请求与连接代次，避免旧回调误断开新连接。

## 有限实机对照

在上述设备上，对 iFan 进行过 60 秒、每 100ms 一次的固定键只读采样：600 次观测均为手动模式、目标 4900 RPM，实际峰值为 4909 RPM，末值为 4901 RPM。采样第一帧已经处于手动模式，证明的是当次持续控制，不是进入手动的瞬间时序。随后恢复系统自动并退出 iFan。

此结果属于第三方程序的对照，不能替代 Mac Go 最终构建的调速或恢复验收。

## 本项目的边界

Mac Go 保留硬件范围验证、外部手动控制保护、写前恢复记录、精确 XPC 身份校验和失败恢复。它不复制 iFan 二进制进入产品，不借用 iFan 的管理员服务，也不降低权限检查。

真实转速与恢复仍须使用最终构建单独验收；模拟测试用于覆盖状态机差异。
