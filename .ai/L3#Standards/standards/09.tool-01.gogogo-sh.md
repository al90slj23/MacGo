# gogogo.sh：GitHub 发布与本机应用更新

Mac Go 的统一入口负责验证源码、发布到 GitHub，以及更新和启动本机应用。没有服务器、线上数据库、SSH 或网站部署步骤。实现入口为根 `gogogo.sh`，实际协调脚本位于 `scripts/`；本规范描述必须保持的门槛。

## 操作

| 命令 | 行为 |
| --- | --- |
| `./gogogo.sh` | 交互菜单；非交互环境显示安全帮助/状态，不默认发布 |
| `./gogogo.sh 0` | 校验并构建，更新和启动本机应用；不提交或推送 Git |
| `./gogogo.sh 1 1` | 校验、按候选清单提交、推送并核对远端，再更新本机应用 |
| `./gogogo.sh 1 1 d` | 同上，使用默认提交说明 |
| `./gogogo.sh 2` | 查看本机源码、候选和运行状态 |
| `./gogogo.sh 3` | 仅校验/构建并保存候选回执，不安装或推送 |
| `./gogogo.sh install` | 仅安装并启动已验证且未变化的候选；过期时停止 |
| `./gogogo.sh plan` | 只读展示变更和目标，不运行构建、安装或推送 |
| `./gogogo.sh ai status` | 检查知识检索状态 |
| `./gogogo.sh ai refresh` | 在文档批量变更后刷新检索，失败须报告 |

执行前核对脚本帮助；未知参数必须报错，不能降级成默认发布。没有经过用户选择的发布动作，不隐式提交/推送。

## 候选与验证

1. 检查真实仓库根目录、当前分支、Git 操作状态和发布锁。并发调用不能同时更新应用或候选回执。
2. 在校验前封存 Git 可见的精确候选路径与内容指纹，包括文件内容、删除、符号链接及可执行模式；忽略路径不进入公开发布集。现有暂存或并发变化须清楚处理，不混入未审阅工作。
3. 执行与变更有关的知识/脚本检查、发布脚本回归、`swift test`、Release 构建和严格签名验证。常规流程不调节真实风扇、不重置 TCC、不自动安装 root 服务。
4. 校验完成后再次核对源码指纹。最终包标记对应源码版本及候选身份，回执同时绑定 HEAD、源码指纹和整个应用包内容。源文件、HEAD 或包变动均使旧回执失效。
5. 保留配置的 `CODE_SIGN_IDENTITY`；不得在封装元数据时悄悄降级为临时签名。

## GitHub 发布

只发布到预期 `al90slj23/MacGo` / `main`。核对 fetch/push URL，获取并验证远端历史：只有远端是本地 HEAD 祖先时才能继续；不自动变基，不强推。

只暂存本次封存并审阅的候选清单，不执行整仓 `git add -A`；提交前后核对索引/源码，钩子产生变化时停止并重新验证。推送后直接读取远端 SHA，必须等于预期提交才进入“GitHub 完成”状态；推送失败不继续安装。

GitHub 发布成功和本机更新成功分别记录。远端已更新而本机失败时，准确报告两者，不伪装成原子事务或自动改写 Git 历史。

## 本机更新

- 目标固定为 `~/Applications/Mac Go.app`。旧规范包名只用于受控升级与回退；不得覆盖任意同名路径或无关应用。
- 先验证候选/身份，再正常请求旧应用退出。确认旧进程的当前用户、可执行文件位置和退出结果，给风扇会话执行既有恢复流程；不得用宽泛进程名强杀或覆盖运行中的包。
- 使用临时目录构建和分阶段替换，保留上个应用包；失败保留证据并尝试恢复原应用。仅刷新规范应用路径的 Launch Services 注册，不注册构建或隐藏备份。
- 启动固定安装路径后，有限等待并验证当前用户、实际可执行路径、PID、版本和封存源码身份。`open` 返回成功、旧回执存在或进程同名都不等于更新已运行。
- 安装、启动和权限分别检测。当前签名失效时由集中授权入口指导用户为最终应用授权；管理员服务须由用户完成原生确认。不能在脚本中输入密码、修改 TCC 或弱化 XPC 校验。
- 不因为发布流程顺利而声称窗口激活或实际风扇 RPM 已验收。硬件写入测试须另有明确实机范围，并在结束时核对恢复。

## 本地记录与失败

发布锁、候选回执、运行回执和步骤日志只存放本机忽略目录，不能提交到公开仓库。输出区分校验、提交、推送、替换、启动和权限状态，保留失败步骤及回退路径。安装/运行核对失败后停止，不自动重复推送或循环重启。
