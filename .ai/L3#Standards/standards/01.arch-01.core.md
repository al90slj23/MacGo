# 原生架构与模块所有权

Mac Go 使用一个原生 macOS 应用承载多个工具。按 SwiftPM target 和工具领域划分职责，路径应能说明所有权；不套用 Web 页面到表/API 的映射。

- `MacGo` 处理 AppKit 生命周期、设置与菜单入口、窗口和风扇展示。不得把阻塞图像捕获或共享内容枚举放进同步快捷键回调。
- `ToolboxCore` 维护可单独测试的策略和状态模型；`SMCController` 隔离系统传输及硬件格式；`FanHelperProtocol` / `MacToolboxFanHelper` 限制特权控制协议和恢复职责。
- 主窗口与菜单栏共享同一个已校验的风扇控制会话。异步请求、超时和状态发布须核对连接代次，不能以旧回调破坏新会话。
- 设置按工具领域隔离。共用视觉组件不等于共用功能状态；不得让窗口黑名单影响风扇或其他工具。
- 应用进程默认只读，root 服务只接受受限风扇操作及精确已批准身份，禁止扩展为通用命令、任意文件或裸 PID 信任。
- 增加新模块前明确它的启用状态、命名空间、权限和失败/恢复边界。权限进入集中清单，尚未实现的功能不预先申请。

完整产品、安全与实机验收约束见 [原生 macOS 规范](01.arch-03.native-macos.md)，不能用此摘要替代。
